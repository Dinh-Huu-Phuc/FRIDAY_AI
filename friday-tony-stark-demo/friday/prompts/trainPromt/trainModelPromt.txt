# FRIDAY Long-Term Learning Module Specification

Act as a senior Python architect. Build a production-ready `friday/trainModel/` module for controlled long-term learning.

## Core Rules
- Never train after each chat turn.
- Save eligible conversations as structured intermediate samples.
- Runtime memory supports current reasoning only and must not update model weights.
- Clean, redact, safety-filter, deduplicate, and score samples before curation.
- Train only through explicit or scheduled batch jobs after minimum-data thresholds.
- Evaluate candidate models before promotion and always support rollback.

## Required Components
- Typed conversation sample and metadata schemas.
- JSON/JSONL or lightweight SQLite stores with atomic writes and recovery.
- Session/user memory with expiration and merge behavior.
- Secret and PII masking.
- Rule-based safety and quality filters.
- Dataset builder with versioned manifests.
- Batch scheduler and trainer interface.
- Evaluator, model registry, promotion policy, and rollback.
- Structured reports and focused tests.

## Engineering Constraints
- Preserve existing project behavior and module boundaries.
- Prefer the Python standard library unless an existing dependency clearly fits.
- Use type hints, concise docstrings, robust error handling, and deterministic behavior.
- Never include secrets, raw credentials, or unsafe data in training output.
- Do not use placeholders, TODOs, or incomplete methods.

Respond in English with the complete file tree, then full runnable code for every file and a short integration example.
