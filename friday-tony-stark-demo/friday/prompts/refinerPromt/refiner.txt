Bạn hãy đóng vai kỹ sư phần mềm Python cấp cao và viết full code production-ready để bổ sung tính năng “STT Correction / Refiner” cho project trợ lý AI `friday-tony-stark-demo/friday`.

Bối cảnh:
- Đây là project Python cho trợ lý AI F.R.I.D.A.Y.
- Hệ thống hiện đã có Agent, prompts, tools, messages, config, search...
- Đầu vào từ micro sẽ đi qua dịch vụ STT như Deepgram hoặc Google Speech-to-Text.
- Văn bản STT trả về thường có lỗi chính tả, thiếu dấu, sai tên riêng, sai ngữ cảnh hoặc nghe nhầm lệnh.
- Tôi muốn thêm một lớp “tinh chỉnh văn bản STT” trước khi đưa câu đó vào Agent để tăng độ chính xác.

Mục tiêu chính:
- Thêm một module mới trong `friday/refiner/` để sửa lỗi câu STT trước khi Agent xử lý.
- Ưu tiên dùng Groq API vì tốc độ nhanh.
- Thiết kế phải cho phép fallback hoặc dễ mở rộng sang OpenAI sau này.
- Hệ thống phải giữ nguyên ý nghĩa câu nói của người dùng, chỉ sửa lỗi nhận dạng, lỗi chính tả, lỗi thiếu dấu, lỗi tên riêng, lỗi ngữ cảnh nói chuyện với trợ lý.
- Không biến câu nói thành văn phong khác hẳn.
- Không trả lời thay người dùng. Chỉ tinh chỉnh câu input.

Cấu trúc mong muốn cần được tạo và tích hợp:
- `friday/refiner/__init__.py`
- `friday/refiner/stt_corrector.py`
- `friday/refiner/custom_vocab.py`
- cập nhật `friday/prompts/templates.py`
- cập nhật `friday/agent_friday.py`
- cập nhật `friday/config.py`
- nếu cần, cập nhật `.env.example`

Kiến trúc mong muốn:
1. `refiner/custom_vocab.py`
   - Chứa danh sách từ chuyên biệt, tên riêng, từ dễ nghe nhầm.
   - Ví dụ:
     - Friday
     - F.R.I.D.A.Y.
     - Jarvis
     - Tony Stark
     - Smart Home
     - tên phòng, tên thiết bị, tên người thân, lệnh nội bộ
   - Hỗ trợ:
     - danh sách từ khóa
     - alias map
     - hàm lấy context vocabulary dưới dạng text để chèn vào prompt
     - hàm normalize đơn giản nếu cần

2. `refiner/stt_corrector.py`
   - Viết class rõ ràng, ví dụ `STTCorrector`
   - Chức năng:
     - nhận raw transcript từ STT
     - nhận thêm context nếu có: user language, conversation hints, custom vocab
     - gọi Groq để sửa câu
     - chỉ trả về câu đã được tinh chỉnh
   - Có provider abstraction gọn gàng để sau này đổi sang OpenAI dễ dàng
   - Có timeout, xử lý lỗi, fallback an toàn
   - Nếu API lỗi, trả về câu gốc hoặc câu đã normalize nhẹ, không làm vỡ luồng hệ thống
   - Có thể thêm rule-based preprocessing trước khi gửi AI
   - Có post-processing để loại bỏ dấu ngoặc kép thừa, lời giải thích thừa, markdown thừa
   - Không được để model trả về phân tích dài dòng, chỉ lấy câu đã sửa

3. `friday/prompts/templates.py`
   - Thêm prompt mẫu cho STT correction, ví dụ `STT_REFINER_PROMPT`
   - Prompt phải đủ mạnh để model hiểu:
     - đây là văn bản từ speech-to-text
     - có thể sai chính tả, thiếu dấu, sai dấu, sai ngữ cảnh
     - nhiệm vụ là sửa lại cho đúng
     - giữ nguyên ý định người dùng
     - không trả lời câu hỏi
     - không thêm thông tin ngoài câu gốc
     - ưu tiên ngữ cảnh trợ lý ảo tiếng Việt
     - ưu tiên đúng các từ trong custom vocab
   - Prompt phải tối ưu cho tiếng Việt tự nhiên

4. `friday/config.py`
   - Bổ sung config để đọc:
     - `GROQ_API_KEY`
     - `GROQ_MODEL`
     - `OPENAI_API_KEY` nếu cần dự phòng
     - `STT_REFINER_ENABLED`
     - `STT_REFINER_PROVIDER`
     - `STT_REFINER_TIMEOUT`
   - Nếu project đang có pattern config sẵn thì bám theo pattern đó
   - Không phá logic cũ

5. `friday/agent_friday.py`
   - Tích hợp refiner vào luồng xử lý:
     - Mic / STT engine -> raw text
     - raw text -> refiner
     - refined text -> agent logic hiện tại
   - Chỉ thêm vào đúng chỗ cần thiết
   - Không rewrite toàn bộ agent nếu không cần
   - Nếu refiner tắt bằng config thì hệ thống vẫn chạy bình thường với raw text
   - Có logging ngắn gọn:
     - raw transcript
     - refined transcript
     - trạng thái dùng provider nào
     - fallback nếu lỗi
   - Không log lộ key hoặc dữ liệu nhạy cảm quá mức
